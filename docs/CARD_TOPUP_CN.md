## 顾客流程

1. 登录 Sub2API，进入“充值/兑换”。
2. 点击店铺或对应面额商品链接，在云猫寄售付款。
3. 从云猫订单取得卡密，回到 Sub2API 同页输入并兑换。
4. 兑换后查看余额和最近活动。每张码只允许使用一次。

云猫订单和 Sub2API 余额记录是两个系统；购买本身不会让余额自动入账。不能使用自定义 iframe 菜单连接云猫：该组件会给外部 URL 加上用户令牌，而且云猫禁止 iframe 嵌入。站内链接必须是纯公开 HTTPS URL，在新标签页打开。

## 补充库存

1. 在**云端** Sub2API 管理后台“兑换码”中选择“生成兑换码”，类型选“余额”，分别填写 $10、$20、$50、$100 和所需数量。不要在本地实例生成用于云端兑换的码。
2. 生成后先保存四份对应面额的码，逐份核对数量和面值。每个码只导入一个云猫商品；不同面额不可混用。不要用云猫的“随机生成卡密”，否则 Sub2API 不认识这些码。
3. 到云猫“商品 → 自营商品”，在对应商品点击“加卡”，每行一张，导入同一批原文卡密。核对库存增加后再销售。
4. 保存云猫订单号与卡密的内部对应关系，限制该记录的访问。卡密不能发到公开聊天、截图或代码仓库。

## 售后追踪

- 在云猫的该商品“库存”中按卡密查找，核对“未售出/已售出”；订单后台核对付款和交付记录。
- 在云端 Sub2API 管理后台“兑换码”中按**同一串卡密**搜索，核对面值、未使用/已使用、使用者和使用时间。必要时导出 CSV。
- 卡密未兑换：先查云猫订单是否已付款、售出码是否与 Sub2API 码完全一致；不要直接给客户加余额。
- 已兑换但客户说未到账：以 Sub2API 的使用者、使用时间、余额变动为准核对；同一张码不得再发给第二位客户。
- 云猫已售出但 Sub2API 找不到：暂停相应商品，核查导错面额或码来源，处理完再补库存。

目前只有初始四张卡、静态购买入口和人工对账流程。尚未实现云猫订单向 Sub2API 的自动回调或自动补库存，也未做真实付款的端到端验证。
